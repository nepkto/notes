# .NET Memory Management & Performance Optimization

यो मास्टर नोट .NET मा मेमोरी व्यवस्थापन (Memory Management), पर्फमेन्स अप्टिमाइजेसन (Performance Optimization), र मेमोरी लीक (Memory Leak) बाट बच्ने उपायहरू एउटै ठाउँमा बुझ्नका लागि तयार पारिएको हो।

---

## १. Stack र Heap मेमोरी (Stack vs. Heap Memory)

.NET ले डाटा भण्डारण गर्न मेमोरीलाई मुख्य दुई भागमा विभाजन गर्छ:

### क. Stack (स्ट्याक)
* **प्रकृति:** व्यवस्थित, सिमित आकार र अत्यधिक छिटो हुने मेमोरी। यसले **LIFO (Last In, First Out)** नियममा काम गर्छ।
* **कस्तो डाटा बस्छ:** यहाँ **Value Types** (`int`, `bool`, `struct`, `ValueTask`) र लोकल वेरिएबल्स बस्छन्।
* **मेमोरी खाली गर्ने:** मेथडको काम सकिने बित्तिकै यहाँको डाटा स्वचालित रूपमा तुरुन्तै हट्छ (Pop)। यसका लागि Garbage Collector चाहिँदैन।

### ख. Heap (हीप)
* **प्रकृति:** ठूलो र गतिशील (Dynamic) मेमोरी क्षेत्र।
* **कस्तो डाटा बस्छ:** यहाँ **Reference Types** (`class`, `string`, `array`, `Task`) बस्छन्। Stack मा चाहिँ यी अब्जेक्टहरूको ठेगाना (Pointer) मात्र बस्छ।
* **मेमोरी खाली गर्ने:** यसलाई सफा गर्न .NET को **Garbage Collector (GC)** को आवश्यकता पर्छ, जसले गर्दा एप्लिकेसनमा केही लोड (Overhead) पर्छ।

---

## २. Value Type र Reference Type बीचको भिन्नता

| विशेषता | Value Type | Reference Type |
| :--- | :--- | :--- |
| **प्रकारहरू** | `struct`, `enum`, `int`, `bool`, `ValueTask` | `class`, `interface`, `string`, `Task` |
| **मेमोरी** | सिधै **Stack** मा बस्छ। | डाटा **Heap** मा र पोइन्टर **Stack** मा बस्छ। |
| **कपी गर्दा (`=`)** | वास्तविक भ्यालु कपी हुन्छ। एउटा बदल्दा अर्को बदलिँदैन। | मेमोरी ठेगाना (Pointer) कपी हुन्छ। एउटा बदल्दा अर्को पनि बदलिन्छ। |

---

## ३. व्यावहारिक कोड उदाहरण: Behind the Scenes (Step-by-Step Stack Trace)

मेमोरीमा कोड कसरी चल्छ भनी बुझ्न तलका दुईवटा उदाहरण र तिनको स्टेप-बाय-स्टेप मेमोरी परिवर्तन (Stack Trace) हेरौं:

### उदाहरण क: Value Type (int)
```csharp
void ExecuteValueType()
{
    int original = 10;
    int copy = original; 
    copy = 20;           
}
```

#### 🔄 Step-by-Step Stack Trace & Memory State:

*   **Line 1 (`int original = 10;`):**
    Stack मा `ExecuteValueType` को फ्रेम बन्छ र `original` को लागि ठाउँ छुट्याएर `10` राखिन्छ। Heap पूर्ण रूपमा खाली रहन्छ।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteValueType Frame]  |       |                           |
    | original = 10             |       | (No Allocation)           |
    +---------------------------+       +---------------------------+
    ```

*   **Line 2 (`int copy = original;`):**
    Stack मा `copy` नामको नयाँ र छुट्टै बाकस बन्छ। `original` को भ्यालु (`10`) कपी भएर त्यहाँ बस्छ।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteValueType Frame]  |       |                           |
    | original = 10             |       | (No Allocation)           |
    | copy     = 10             |       |                           |
    +---------------------------+       +---------------------------+
    ```

*   **Line 3 (`copy = 20;`):**
    Stack मा रहेको `copy` को मान मात्र बदलिएर `20` हुन्छ। `original` जस्ताको तस्तै `10` नै रहन्छ।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteValueType Frame]  |       |                           |
    | original = 10             |       | (No Allocation)           |
    | copy     = 20             |       |                           |
    +---------------------------+       +---------------------------+
    ```

### उदाहरण ख: Reference Type (class)
```csharp
void ExecuteReferenceType()
{
    Score original = new Score() { Value = 10 }; 
    Score copy = original;                       
    copy.Value = 20;                             
}
```

#### 🔄 Step-by-Step Stack Trace & Memory State:

*   **Line 1 (`Score original = new Score() { Value = 10 };`):**
    `new` कीवर्डले गर्दा Heap मा `Score` अब्जेक्ट बन्छ (मानौँ ठेगाना `0x555` हो)। Stack मा रहेको `original` वेरिएबलले त्यो ठेगाना मात्र समात्छ।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteRefType Frame]    |       |                           |
    | original = [0x555] -------|------>| 0x555: Score Object       |
    +---------------------------+       |         - Value: 10       |
                                        +---------------------------+
    ```

*   **Line 2 (`Score copy = original;`):**
    Stack मा `copy` वेरिएबल बन्छ। यसले `original` मा भएको भ्यालु कपी गर्छ, जुन केवल एउटा ठेगाना (`0x555`) हो। अब दुवैले Heap को एउटै अब्जेक्टलाई इसारा गर्छन्।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteRefType Frame]    |       |                           |
    | original = [0x555] -------|------>| 0x555: Score Object       |
    | copy     = [0x555] -------|------/          - Value: 10       |
    +---------------------------+       +---------------------------+
    ```

*   **Line 3 (`copy.Value = 20;`):**
    C# ले Stack मा `copy` को ठेगाना (`0x555`) हेर्छ र Heap को सोही ठाउँमा गएर `Value` लाई `20` बनाउँछ। परिणामस्वरुप, `original.Value` पनि स्वतः `20` देखिन्छ।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteRefType Frame]    |       |                           |
    | original = [0x555] -------|------>| 0x555: Score Object       |
    | copy     = [0x555] -------|------>|         - Value: 20       |
    +---------------------------+       +---------------------------+
    ```

*   **Method End (Cleanup):**
    मेथड सकिने बित्तिकै Stack Frame पूरै खाली हुन्छ र पोइन्टरहरू हट्छन्। Heap मा रहेको `0x555` अब्जेक्ट अब टुहुरो (Orphaned) बन्छ र यसलाई पछि **Garbage Collector (GC)** ले सफा गर्छ।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    |                           |       |                           |
    | (Stack is cleared)        |       | 0x555: Score Object (Trash|
    |                           |       |        Waiting for GC)    |
    +---------------------------+       +---------------------------+
    ```

### उदाहरण ग: Special Reference Type (string - Immutable)
```csharp
void ExecuteStringCopy()
{
    string original = "abc";
    string copy = original;
    copy = "xyz";
}
```

#### 🔄 Step-by-Step Stack Trace & Memory State:

*   **Line 1 (`string original = "abc";`):**
    `string` एउटा Reference Type भएकोले यसको मुख्य डाटा `"abc"` Heap मा बस्छ (मानौँ ठेगाना `0x111` हो)। Stack मा रहेको `original` वेरिएबलले यो ठेगानालाई पोइन्ट गर्छ।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteString Frame]     |       |                           |
    | original = [0x111] -------|------>| 0x111: "abc"              |
    +---------------------------+       +---------------------------+
    ```
*   **Line 2 (`string copy = original;`):**
    Stack मा `copy` वेरिएबल बन्छ र यसले `original` मा भएको ठेगाना (`0x111`) कपी गर्छ। अब दुवैले Heap को एउटै टेक्स्टलाई हेरिरहेका छन्।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteString Frame]     |       |                           |
    | original = [0x111] -------|------>| 0x111: "abc"              |
    | copy     = [0x111] -------|------/                            |
    +---------------------------+       +---------------------------+
    ```
*   **Line 3 (`copy = "xyz";`):**
    स्ट्रिङ **Immutable** (परिवर्तन नहुने) हुने भएकोले .NET ले `0x111` मा रहेको डाटा बदल्न सक्दैन। यसले Heap मा `"xyz"` को **नयाँ अब्जेक्ट** बनाउँछ (ठेगाना `0x222`) र Stack को `copy` पोइन्टरलाई त्यहाँ सारिदिन्छ। `original` मा अझै पनि `"abc"` नै रहन्छ।
    ```text
    STACK                               HEAP
    +---------------------------+       +---------------------------+

    | [ExecuteString Frame]     |       | 0x111: "abc" (original)   |
    | original = [0x111] -------|------>|                           |
    | copy     = [0x222] -------|------>| 0x222: "xyz" (copy)       |
    +---------------------------+       +---------------------------+
    ```

## ४. Task र ValueTask (Task vs. ValueTask)

एसिन्क्रोनस प्रोग्रामिङ (`async/await`) मा मेमोरी बचाउन `ValueTask` को अवधारणा ल्याइएको हो।

* **Task<T> (Reference Type - Heap Allocated):**
  * यो एउटा `class` हो, त्यसैले यो Heap मा बस्छ।
  * **कहिले प्रयोग गर्ने:** जब अपरेशन वास्तवमै ढिलो हुन्छ र धेरैजसो समय एसिन्क्रोनस रूपमा चल्छ (जस्तै: नेटवर्क वा API कल गर्दा)।

* **ValueTask<T> (Value Type - Stack Allocated):**
  * यो एउटा `struct` हो, त्यसैले यो Stack मा बस्छ। 
  * **फाइदा:** जब कुनै एसिन्क्रोनस अपरेशन धेरैजसो समय तुरुन्तै अर्थात् सिन्क्रोनस रूपमा पूरा हुन्छ (जस्तै: डाटा पहिले नै क्यास वा मेमोरीमा उपलब्ध हुँदा), यसले Heap मा कुनै नयाँ अब्जेक्ट बनाउँदैन (Zero Heap Allocation)।

## ५. स्ट्रिङ अप्टिमाइजेसन: StringBuilder, ReadOnlySpan, र Memory

स्ट्रिङ अपरेशनहरूमा Heap मेमोरी जोगाउन .NET मा आधुनिक टूल्स प्रयोग गरिन्छ:

### क. StringBuilder (Mutable String Buffer)
लुप (Loop) भित्र सामान्य `text += "A"` गर्दा Heap मा हरेक पटक नयाँ स्ट्रिङ अब्जेक्ट बन्छ। `StringBuilder` प्रयोग गर्दा बीचका बेकारका पुराना स्ट्रिङ अब्जेक्टहरू बन्न पाउँदैनन् र एउटै आन्तरिक बफर (Character Array) मा डाटा थपिन्छ।

### ख. ReadOnlySpan<char> (Zero Allocation Window for Stack)
यो एउटा `ref struct` हो जुन सधैं Stack मा मात्र बस्छ।
* **फाइदा:** सामान्य `.Substring()` ले Heap मा नयाँ स्ट्रिङ अब्जेक्ट बनाउँछ, तर `.AsSpan().Slice()` ले मूल स्ट्रिङकै मेमोरी ठेगाना र लम्बाइलाई मात्र Stack बाट पोइन्ट गर्छ। यसले बिना कपी स्ट्रिङ टुक्राउने काम गर्छ।
* **सिमितता:** Stack मा मात्र बस्ने हुनाले यसलाई `async` मेथडको `await` क्रस गरेर प्रयोग गर्न मिल्दैन।

### ग. Memory<T> (The Async-Friendly Span)
यो एउटा सामान्य `struct` हो (Ref Struct होइन)। त्यसैले यो Heap मा पनि जान सक्छ।
* **कहिले प्रयोग गर्ने:** जब तपाईंलाई `Span<T>` को जस्तै Zero-Allocation मेमोरी स्लाइसिङ फिचर चाहिन्छ, तर त्यसलाई **`async/await` मेथडहरूमा** वा क्लासको सामान्य **Field** को रूपमा प्रयोग गर्नु पर्ने हुन्छ।

## ६. Boxing र Unboxing

* **Boxing:** Value Type लाई Reference Type (`object`) मा बदल्ने महँगो प्रक्रिया हो, जसले डाटालाई Stack बाट **Heap** मा सार्छ र नयाँ अब्जेक्ट बनाउँछ।
* **Unboxing:** Boxed भएको `object` लाई पुनः यसको वास्तविक Value Type मा फर्काउने प्रक्रिया हो (यसमा कास्टिङ `(int)` आवश्यक हुन्छ)।

**असर:** Boxing/Unboxing ले Heap मा अनावश्यक लोड बढाउँछ र Garbage Collector लाई व्यस्त बनाउँछ। आधुनिक C# मा यसबाट बच्न **Generics (`List<T>`)** को प्रयोग गरिन्छ।

## ७. मेमोरी लीक र बच्ने उपायहरू (Memory Leaks & Fixes)

.NET मा Garbage Collector भए पनि प्रोग्रामरको गल्तीले मेमोरी लीक हुन सक्छ। मुख्य तीन कारण र समाधान तल दिइएका छन्:

### क. इभेन्ट अनसबस्क्राइब नगर्दा (Unsubscribed Events)
* **समाधान:** `IDisposable` लागू गरेर `Dispose()` भित्र इभेन्ट अनसबस्क्राइब (`-=`) गर्ने।

### ख. स्ट्याटिक रेफरेन्स (Static References)
* **समाधान:** डाटा निश्चित समयपछि हटाउने वा **`WeakReference<T>`** को प्रयोग गर्ने ताकि GC ले आवश्यक पर्दा सफा गर्न सकोस्।

### ग. IDisposable बन्द नगर्दा (Unmanaged Resources)
* **समाधान:** सधैं **`using`** ब्लक प्रयोग गर्ने, जसले काम सकिएपछि स्वतः रिसोर्स बन्द (`Dispose`) गरिदिन्छ।
