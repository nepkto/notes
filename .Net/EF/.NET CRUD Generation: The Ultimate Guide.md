## 1. Introduction & Laravel vs .NET Comparison

In Laravel, a single command generates a model, migration, and controller. In .NET, the philosophy is explicit, separating concerns. However, by leveraging both the **.NET CLI** and **Visual Studio's built-in tooling** in a unified workflow, you can achieve a similarly rapid development experience.

| Creation Type | Laravel Command | .NET CLI Command | Visual Studio GUI Action |
| :--- | :--- | :--- | :--- |
| **Model** | `php artisan make:model User` | `dotnet new class -n User -o Models` | Right-click → Add → Class |
| **Migration** | `php artisan make:migration create_users` | `dotnet ef migrations add CreateUsers` | Package Manager Console: `Add-Migration` |
| **Controller** | `php artisan make:controller UserController`| `dotnet new apicontroller -n UsersController`| Right-click → Add → Scaffolded Item |
| **All-in-One** | `php artisan make:model User -m -c` | *Custom PowerShell Script* (See Section 5) | *Scaffolding Wizard* (Partial) |

## 2. Step 1: Creating a Model

**Action:** Create the model file using your preferred tool.
*   **⚡ CLI:** Run `dotnet new class -n User -o Models`
*   **🖥️ Visual Studio:** In Solution Explorer, right-click the `Models` folder → **Add** → **Class...** → Name it `User.cs`. *(💡 Pro Tip: Inside the class, type `prop` and press `Tab` twice to instantly generate properties).*

**Code:** Open `Models/User.cs` and add your properties and Data Annotations:

```csharp
using System.ComponentModel.DataAnnotations;

namespace MyApi.Models
{
    public class User
    {
        [Key]
        public int Id { get; set; }

        [Required]
        [MaxLength(100)]
        public string Name { get; set; } = string.Empty;

        [Required]
        [EmailAddress]
        public string Email { get; set; } = string.Empty;

        public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    }
}
```

## 3. Step 2: Creating a Migration

> ⚠️ **Crucial Step:** Always **Build** your project first (`Ctrl + Shift + B` in VS or `dotnet build` in CLI) to ensure no compilation errors exist before generating a migration.

**Action:** Generate and apply the migration using your preferred tool.
*   **⚡ CLI:** 
    ```bash
    dotnet ef migrations add CreateUsersTable
    dotnet ef database update
    ```
*   **🖥️ Visual Studio (Package Manager Console):** 
    1. Go to **Tools** → **NuGet Package Manager** → **Package Manager Console**.
    2. Ensure the **Default project** dropdown is set to your main project.
    3. Run:
       ```powershell
       Add-Migration CreateUsersTable
       Update-Database
       ```

**Result:** EF Core will generate a migration file in your `Migrations` folder and apply the schema changes to your database.

## 4. Step 3: Creating a Controller

**Action:** Create the controller using your preferred tool.
*   **⚡ CLI:** Run `dotnet new apicontroller -n UsersController -o Controllers`
*   **🖥️ Visual Studio (Scaffolding):** 
    1. Right-click the `Controllers` folder → **Add** → **New Scaffolded Item...**
    2. Select **API Controller with actions, using Entity Framework** → **Add**.
    3. **Model class:** Select `User`.
    4. **Data context class:** Select `ApplicationDbContext`.
    5. ✅ Check **Use async controller actions** → **Add**.

**Code (Production-Ready Service Layer Pattern):**
*Whether you used CLI or VS Scaffolding, it is highly recommended to refactor the generated controller to use a Service Layer and DTOs instead of directly injecting the DbContext.*

```csharp
using Microsoft.AspNetCore.Mvc;
using MyApi.Services;
using MyApi.DTOs; 

namespace MyApi.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class UsersController : ControllerBase
    {
        private readonly IUserService _userService;
        private readonly ILogger<UsersController> _logger;

        // Inject Service, NOT DbContext directly
        public UsersController(IUserService userService, ILogger<UsersController> logger)
        {
            _userService = userService;
            _logger = logger;
        }

        [HttpGet]
        public async Task<ActionResult<IEnumerable<UserResponseDto>>> GetUsers()
        {
            var users = await _userService.GetAllAsync();
            return Ok(users);
        }

        [HttpPost]
        public async Task<ActionResult<UserResponseDto>> CreateUser([FromBody] CreateUserRequestDto request)
        {
            if (!ModelState.IsValid) return BadRequest(ModelState);
            var user = await _userService.CreateAsync(request);
            return CreatedAtAction(nameof(GetUsers), new { id = user.Id }, user);
        }
        
        // Add Put and Delete methods following the same async/DTO pattern
    }
}
```

## 5. The All-in-One Automation Script

To replicate the Laravel `php artisan make:model User -m -c` experience, use this PowerShell script. It creates the Model, updates the DbContext, generates the Migration, creates the Controller, and updates the Database in one go.

> **Setup:** Save this as `make.ps1` in your project root. Run it via the **Visual Studio Integrated Terminal** (`View` → `Terminal`) or any PowerShell window.

```powershell
# make.ps1 - Usage: .\make.ps1 User
param(
    [Parameter(Mandatory=$true)]
    [string]$Name,
    [string]$Namespace = "MyApi"
)

$pluralName = $Name + "s"
$lowerPlural = $pluralName.ToLower()

Write-Host "🚀 Creating Model, Migration, and Controller for $Name..." -ForegroundColor Cyan

# 1. Create Model
if (!(Test-Path "Models")) { New-Item -ItemType Directory -Path "Models" | Out-Null }
$modelPath = "Models/$Name.cs"
$modelTemplate = @"
using System;
using System.ComponentModel.DataAnnotations;

namespace $Namespace.Models
{
    public class $Name
    {
        [Key]
        public Guid Id { get; set; } = Guid.NewGuid();
        [Required]
        [MaxLength(100)]
        public string Name { get; set; } = string.Empty;
        public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    }
}
"@
New-Item -Path $modelPath -Value $modelTemplate -Force | Out-Null
Write-Host "✅ Created Model: $modelPath" -ForegroundColor Green

# 2. Add DbSet to DbContext
$dbContextPath = "Data/ApplicationDbContext.cs"
$dbSetLine = "    public DbSet<$Name> $pluralName { get; set; } = null!;"
if (Test-Path $dbContextPath) {
    $content = Get-Content $dbContextPath -Raw
    if ($content -notmatch "DbSet<$Name>") {
        $content = $content -replace "(?m)(\s+)(\}\s*)$", "`n$dbSetLine`n`$1`$2"
        Set-Content -Path $dbContextPath -Value $content
        Write-Host "✅ Added DbSet<$Name> to ApplicationDbContext" -ForegroundColor Green
    }
} else {
    Write-Host "⚠️ DbContext not found. Add manually: $dbSetLine" -ForegroundColor Yellow
}

# 3. Create Migration
Write-Host "⏳ Building project before migration..." -ForegroundColor Cyan
dotnet build --no-restore | Out-Null
dotnet ef migrations add "Create${pluralName}Table"
Write-Host "✅ Created Migration" -ForegroundColor Green

# 4. Create Controller
if (!(Test-Path "Controllers")) { New-Item -ItemType Directory -Path "Controllers" | Out-Null }
$controllerPath = "Controllers/${pluralName}Controller.cs"
$controllerTemplate = @"
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;
using $Namespace.Models;
using $Namespace.Data;

namespace $Namespace.Controllers
{
    [Route("api/[controller]")]
    [ApiController]
    public class ${pluralName}Controller : ControllerBase
    {
        private readonly ApplicationDbContext _context;
        public ${pluralName}Controller(ApplicationDbContext context) => _context = context;

        [HttpGet]
        public async Task<ActionResult<IEnumerable<$Name>>> Get() => await _context.$pluralName.ToListAsync();

        [HttpGet("{id}")]
        public async Task<ActionResult<$Name>> Get(Guid id)
        {
            var item = await _context.$pluralName.FindAsync(id);
            return item == null ? NotFound() : item;
        }

        [HttpPost]
        public async Task<ActionResult<$Name>> Post($Name item)
        {
            _context.$pluralName.Add(item);
            await _context.SaveChangesAsync();
            return CreatedAtAction(nameof(Get), new { id = item.Id }, item);
        }

        [HttpPut("{id}")]
        public async Task<IActionResult> Put(Guid id, $Name item)
        {
            if (id != item.Id) return BadRequest();
            _context.Entry(item).State = EntityState.Modified;
            await _context.SaveChangesAsync();
            return NoContent();
        }

        [HttpDelete("{id}")]
        public async Task<IActionResult> Delete(Guid id)
        {
            var item = await _context.$pluralName.FindAsync(id);
            if (item == null) return NotFound();
            _context.$pluralName.Remove(item);
            await _context.SaveChangesAsync();
            return NoContent();
        }
    }
}
"@
New-Item -Path $controllerPath -Value $controllerTemplate -Force | Out-Null
Write-Host "✅ Created Controller: $controllerPath" -ForegroundColor Green

# 5. Update Database
Write-Host "⏳ Updating database..." -ForegroundColor Cyan
dotnet ef database update
Write-Host "✅ Updated Database" -ForegroundColor Green
Write-Host "🎉 All done! Test endpoint: /api/$lowerPlural" -ForegroundColor Magenta
```

## 6. Advanced Best Practices

1. **Use DTOs (Data Transfer Objects):** Never expose your database Models directly in API responses. Create `UserResponseDto` and `CreateUserRequestDto` classes. Use **AutoMapper** or **Mapster** to map between Models and DTOs.
2. **Validation:** Apply Data Annotations (`[Required]`, `[StringLength]`) or **FluentValidation** to your *DTOs*, not your database Models.
3. **Service Layer Pattern:** For complex business logic, create an `IUserService` that encapsulates the logic, and inject *that* into the controller (as shown in Section 4).
4. **Global Exception Handling:** Use `UseExceptionHandler` or a custom Middleware to catch errors and return standardized `ProblemDetails` responses instead of raw stack traces.
5. **Pluralization:** EF Core automatically pluralizes table names (e.g., `User` → `Users`). If you want to control this, override `OnModelCreating` in your DbContext or use the `[Table("CustomName")]` data annotation.

## 7. Troubleshooting Common Pitfalls

| Issue | Solution |
| :--- | :--- |
| **"No executable found matching command 'dotnet-ef'"** | Run `dotnet tool install --global dotnet-ef` in your terminal. |
| **"Unable to create an object of type 'ApplicationDbContext'"** | Ensure `Program.cs` has `builder.Services.AddDbContext<ApplicationDbContext>(...)` configured. |
| **Migration is empty (no Up/Down code)** | You forgot to add the `DbSet<YourModel>` to your `DbContext`, or you didn't build the project before running the migration command. |
| **VS Scaffolding: "Model class" dropdown is empty** | **Build the project** (`Ctrl + Shift + B`). The scaffolding engine needs compiled DLLs to reflect the model types. |
| **Controller returns 404** | Ensure the class name ends with `Controller` (e.g., `UsersController`) and has `[ApiController]` and `[Route("api/[controller]")]`. |
| **PowerShell script execution is disabled** | Run PowerShell as Administrator and execute: `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`. |
